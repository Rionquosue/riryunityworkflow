# User tests

Only what needs the Unity Editor or VRChat to see. Wording, file names, log text, menu order and anything else settled by reading the code is checked there, not here. Not committed to any repository.

1. Compiles everywhere: open a project with the VRChat SDK 3.10.6 or newer, YGDR Animator Editor, MACS 1.7.10 and both packages (RiryTools, and com.riry.animatortemplates as a package). The Console should have no errors. Then remove the VRChat SDK (and, separately, YGDR Animator Editor): still no errors, Constraint Tool shows the SDK popup, the templates package's YGDR bridge doesn't compile without YGDR, and its MACS menu doesn't compile without MACS.

2. Menu keys (Windows): open Tools > RiryTools from the keyboard. No label shows "&", and T, C, N and O select Constraint Tool, Clean Animation Keys, Avatar Migration Assistant and IconCap.

3. AutoSync: turn Sync on in a project without Git (it should set up the repository and LFS). Save a scene, a prefab in Prefab Mode, and apply a prefab override: one commit per save, holding only that file and its .meta, pushed to the remote; a file you staged first stays staged and out of the commit. Check out a commit (detached HEAD) and save: it commits but doesn't push.

4. AutoSync sign-in and LFS: add an HTTPS remote that needs a sign-in; saving should open Git's credential manager window (no terminal prompt) and the commit should reach the remote. Configuration should report LFS on for a server with LFS and off for one without, and nothing should appear in the server's LFS storage.

5. AutoSync large files: commit a file over 100 MiB with an HTTPS remote. The ! appears by the remote, Push Held shows once and nothing is pushed. In Large Files, Add to ignore and OK: the file is in .gitignore, still on disk, gone from the unpushed commits, and the next save pushes.

6. AutoSync branch switch: pick another branch in Configuration. Unsaved scenes are offered for saving, the branch is checked out, Unity reloads changed files, and the next save commits to it.

7. Stop Auto Game: with it on, entering Play Mode gives focus back to the window you had (not the Game view); with a layout without a Game view, the one Play Mode opens closes again. Off: plain Unity behaviour.

8. Main Menu look: in dark and light themes, the tabs are equal flat cells with crisp 2 px outlines on every side (top included), a gap above the sub-tabs, and the sub-tabs end at the same right edge as the main tabs. Drag the width slowly: rows wrap and the height changes only when the row count does. Docked, it comes back after a restart. At 480 x 380 every tab's last control is reachable by scrolling with no horizontal scroll bar. In each tab the tool works as in its own window; IconCap and Avatar Migration Assistant open in their own windows. The Constraint Tool window's top outline is visible.

9. Dialogs inside windows: click every button that opens a dialog or file panel (Browse buttons, Build animation with Clip empty, Save as Prefab Overrides, Git Configuration's Save .gitignore, Add Remote, Apply, OK, GUID Tools, Broken References Rescan and Apply, Clean, Extract, Save Mockup over an existing name), also inside the Main Menu. After each closes, no EndLayoutGroup, GUILayout or "Getting control" errors and the window redraws normally.

10. Clean Animation Keys: right-click several .anim files > Clean Animation Keys. The list scrolls instead of growing; whitelist suggestions appear as you type, and at minimum size the content scrolls with Clean staying at the bottom. Clean asks first, then one Ctrl+Z restores every clip. In the Animation window, the Clean Keys button sits right of Dopesheet and Curves and never covers them, the time ruler or events, even with the pane divider dragged far left.

11. Extract Animation: on an FBX with animations, Extract puts the clips in Destination. With Automatically clean keys and Save animation extract settings on, the settings file appears beside the FBX (hidden, no .meta, staged in Git), and Configure lists the extracted clips. With Automatically extract on and a Humanoid preset applied to the folder, the clips are extracted before the model turns Humanoid. Ctrl+Z after changing Destination or a toggle puts it back and the file follows.

12. Extraction and Undo: move an object, then import an FBX into a folder that auto-extracts and auto-cleans: Ctrl+Z undoes your move, not the import. Extract by button, change the FBX's animation, extract again with Replace: one Ctrl+Z brings back the earlier clip contents, keeping the file. Two models named Body.fbx in different folders extracting to the same Destination: the second must not change the first's clips.

13. Folder import presets: in Set Folder Import Presets (window and right-click popup), choose presets and Apply. It asks first when files will be reimported (Cancel changes nothing); then only files whose type's preset changed are reimported, subfolder files untouched, and a new file dropped in the folder (including an _normal decorator file) imports with its preset. A new type of file dropped into the folder shows up in the window without clicking anything. Save Import Preset on a texture: the preset is then offered for another image type in another folder. With Better FBX on, a .blend is exported.

14. GUID repair by redirect: in a Git project, break a material's GUID in its .meta. The scene shows it missing; Check for Broken References offers the material (found in Git history), Apply brings it back. Without Git, the row stays red until you pick the asset by hand. Selecting the whole Assets folder, Apply stays reachable.

15. GUID repair by restore: delete a committed material (and its .meta). Restore from Git brings it back with its old GUID (an LFS texture comes back as the image). If its path is taken by another file, it is restored beside it and the other file is untouched. A restored file that uses a missing texture shows Break detected; Fix adds the texture as its own row; leaving a break unfixed asks before applying. A chain three restores deep (scene > prefab A > prefab B > material > texture) shows RECURSIVE BREAK DETECTED at the third level, and after Apply the window goes on to the next pass by itself until nothing is broken. A missing script is never listed.

16. Saving with broken references: with a broken reference in an open scene, Ctrl+S stops with the red warning; ABORT leaves the file unchanged, and CONTINUE ANYWAY saves on the third click. Same in Prefab Mode. A scene whose only problem is a missing script saves normally. Opening a broken scene shows the repair prompt, not the save warning; Do Not Show Again silences it for that scene only. If the save warning appears on scene entry, click ABORT and send the Console stack of the aborted save.

17. Regenerate GUID: regenerate a scene's GUID (one with Blendshape Sync jobs): references keep working and its jobs are still there after the reload. Put the asset's GUID into a .txt under Assets and regenerate: it asks first, and Cancel changes nothing.

18. Menu Mockup: add Click Button, Text Box and Block from Components and drag Label onto a spot in Edit. Handles resize; dragging a block over another opens a gap after half a second; dropping into a Block nests it; double-click edits text live; right-click layout options change the layout. Save, close both windows, Load: the layout and window size come back. Each move, resize, text, style, Delete and New is one Ctrl+Z.

19. Blendshape Sync: make a job (body master, shirt child, Run automatically) and close its popup: the shirt keeps following. In the Main Menu tab, untick Auto (stops), Sync Now (catches up), Edit, Set All to Original (restores, still after you Ctrl+Z a Run automatically change), and Remove (asks; stays gone after reopening the scene). Below 570 px the buttons move under the name. Restart Unity: the job comes back with Auto and children. With jobs A and B on Auto, Ctrl+Z of A's sync stops only A. Dragging a master slider for 3 seconds is one Ctrl+Z. Dragging a slider in a job popup writes the job file once, about a second after you let go.

20. Blendshape Sync job safety: making a renderer a child in two jobs, or two jobs sync each other, is refused. Break a master's link (re-add its prefab instance), reopen and save the scene: the job is skipped with a warning but stays in the file, and comes back once the object is restored.

21. IconCap preview and capture: orbit the Scene view and the preview follows within about 0.1 s; docked behind another tab, no IconCap camera renders (Profiler). A Transparent capture's alpha matches the silhouette with no offset or flip; Opaque, Transparent with background, HDRI and Flat lighting all look right. Alpha cutout makes clipped holes (Standard, lilToon, Poiyomi cutout) transparent; off, solid; unclipped materials are always solid.

22. IconCap exclusions and objects: each Exclude switch changes only its own lighting, and afterwards the scene is as before (lights on, not dirty, Lighting window unchanged). Capture only selected off shows only skinned meshes; on, the first slot follows the selection until two are filled; Isolated item captures only it while the Scene view shows everything.

23. IconCap effects: each effect type looks right in the preview and a saved PNG; reorder (top applied last), toggle and remove work. Outline thickness and Overlay/Draw under position and scale match between the preview and a 4096 capture (X 50 moves right 50 px at 512, Y 50 down, scale 0.5 halves around the centre, no tiling).

24. IconCap saving and jobs: Camera holds the capture options (no Capture options or This session foldouts); Jobs shows two boxes, Current job (captures, Save job on its title row) and Saved jobs (empty with no jobs). Save as PNG pings the file; Save again overwrites it keeping its GUID; a Current job row moves the camera back and reselects. Save job, move the camera, Run: it asks first, then remakes the icons from their saved cameras and moves the old ones to OLD_n, and a material using an icon shows the new one. Change Size, capture twice, export one, Ctrl+Z: only Size goes back. Presets bring back everything but the view, and ask before replacing one of the same name.

25. Icon Generator: sources show their results beside them; Regenerate writes outputs beside the asset; renaming a source renames its output keeping the GUID; a Template's stack is used. Two sources of the same name, or an unrelated PNG at an output's path, are reported and never overwritten.

26. IconCap narrow: at 360 px, no horizontal scroll bar anywhere and nothing overlaps (Prefix/Suffix, the Job row, Restore, Crop and zoom, Drop shadow, Jobs with long names, Icon Generator thumbnails, session rows with long names keep Export and Remove visible).

27. Avatar Migration matching: two humanoids with different bone names match without being listed; a renamed hair bone in the same place matches by structure, moved by more than 0.001 it is unmatched with everything below it. A renamed body object matches by Mesh (also with the mesh renamed). An unpacked jacket directly under the old root is never matched to the body. In Manual matching, a wrong path turns red and greys Continue; setting an unmatched parent fills the rows below; your own entries survive re-matching, and editing other rows keeps a Mesh match; headers line up when scrolling; Cancel changes nothing.

28. Avatar Migration copy and Ctrl+Z: copy PhysBones, colliders, contacts and constraints. The collider lists point at the new avatar, nothing on the new avatar points at the old one, the old avatar never changes, and one Ctrl+Z restores the new avatar exactly. Copy twice on Add: no duplicates. Replace: the target's are replaced, except on ignored objects and inside outfit prefab instances. The up-front check lists issues and asks its questions; Abort changes nothing; the bounds question shows only while skinned settings are Yes, with no errors when flipped.

29. Avatar Migration corrections: an old build at scale 0.01 to a new one at 1: a collider radius of 0.0008 becomes about 0.08 and sizes match in the Scene view. A Parent constraint on a bone whose roll differs keeps the accessory facing exactly as before.

30. Avatar Migration prefabs and objects: an accessory prefab under the old head arrives under the new head as a prefab instance with its override. An extra hair bone is created with Create missing objects on. With VRC constraint upgrade Yes, the target gets VRC constraints sourced on the new avatar, the old keeps its Unity ones, one Ctrl+Z undoes it with a clean Console, Ctrl+Y redoes it, and no hidden constraint copy remains.

31. Avatar Migration descriptor and types: viewpoint, visemes, eye bones and colliders point at the new avatar; the blueprint ID is copied only when ticked. An entry added to types.yml appears and copies when ticked. Ignoring an object on the target skips its source counterpart.

32. Unpacked prefabs placed again: on the old avatar, unpack an outfit model completely, unpack an accessory model inside it, then rename its mesh object and a bone, move an object, change a material, add a PhysBone, delete an object, and remove a component another needs. Migrate to a fresh packed avatar prefab and answer Yes. Both arrive as prefab instances (the accessory inside the outfit), every change as an override (renames as name overrides, the deleted object removed, the needed component kept), with no Unity error, and the outfit ticked under Child prefabs on the target. One Ctrl+Z takes it all back.

33. Avatar Migration new body mesh: with material slots reordered, each material lands on the same part; a material used on two slots fills both. With blendshapes renamed or dropped, the report lists the lost values, visemes or mouth-open (only those the Lip Sync mode uses), eyelids, and animated blendshapes; eyelids that exist point at the right shapes in Eye Look. With a changed mesh, old bounds are copied only when you say Yes.

34. Retarget animations: duplicated controllers and clips appear under the migrated folder at their original paths, the descriptor points at them, toggles drive the new avatar, and the originals are unchanged, including a blend tree saved as its own asset (no copy-of-a-copy clips when two states share one). A VRCFury Full Controller in an included clothing prefab gets Path Rewrite Rules as a scene override and merges in Play mode; an unticked prefab is untouched.

35. Attach To: select an avatar (or a bone of it), then an accessory: Target avatar fills, also for a humanoid without a descriptor, and an accessory's own generic Animator doesn't replace it. The popup lists the common bones (hover shows the object name), Add bone and Remove persist across restarts, and generic avatars, armatures without an Animator (Hand_L, J_Bip_L_UpperArm, mixamorig:LeftHand) and objects with none behave sensibly.

36. Attach To snapping: a rotated, scaled accessory to Head, No: same global position, rotation and scale unchanged, one Ctrl+Z. Yes: it becomes a child keeping its global transform, one Ctrl+Z. Three accessories: one prompt, all move. A child inside a prefab instance: Skip leaves it packed and snapped; Unpack unpacks only the levels needed. A prefab instance root moves with no warning. Under a non-uniformly scaled bone, note how far off the scale is.

37. Train: Generate all missing chains, Set up constraints, Build animation and Save as Prefab Overrides work in the window and the Main Menu sub-tab. One Ctrl+Z removes every generated chain and empties the slots, Ctrl+Y brings them back. Save as Prefab Overrides applies only the train (an accessory's constraint change and an object named Rest_Test stay as instance overrides). Using the Hierarchy entry on another bone, then Ctrl+Z, returns to the first bone with its chains.

38. Bezier: on a 5+ bone tail, Generate rig rotates nothing and moves bones only by the shown Rest fit (none with Keep length). Moving anchors and handles bends the chain live along a smooth curve; Handles follow anchors carries the handles. Stretch keeps every bone on the curve; Keep length keeps lengths. Mechanism chain puts the curve on a Bezier_ copy with each real bone following it exactly. Existing keeps uneven spacing, Even spreads it. Twist from anchors twists gradually. Remove rig asks, removes only what Generate added, and each is one Ctrl+Z; nothing unpacks on a prefab instance.

39. Insertable prop in the editor: the tab exists (Main Menu too); with an SDK older than 3.10.6 it says so and Train and Bezier still work. Generate puts the dagger seated in the sheath, the layers and parameters in the chosen controller, and the prefab asset is unchanged. The Seated pose and Socket opening handles start apart with readable labels; moving them and Update pair re-seats it with nothing duplicated. Ctrl+Z after Generate (three times over) leaves no IP_ sub-assets in the controller. Remove (keep clips, or delete clips) removes only the pair. Two same-named avatars with their own controllers keep separate clips; sharing a controller asks first.

40. Insertable prop in VRChat (ideally with a friend): (1) grabbed by you, the dagger follows your hand and wrist roll; by another player, their hand's pitch and yaw with the edge toward world up; note jitter and the right Grip smoothing; (2) released with the tip in the capture radius, from the front and the side, it aims in, reaches the entry and slides home for both viewers; note any visible hand-off; (3) PC: released elsewhere it falls, hits the world and stays as you walk 10 m away; thrown, it keeps speed and spin; either permitted player can pick it up; note landing differences between viewers; (4) Android build: it lies on the floor below where released and can be picked up; (5) a player without finger contacts: it aims at the sheath and slides back on release; (6) note the distance where it stops following (about 10 m expected); (7) seated or dropped, the PhysBone end sits on the grip and grabbing works first time.
